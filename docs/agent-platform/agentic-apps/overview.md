# Agentic Apps

Agentic Apps are autonomous systems that orchestrate multiple specialized AI agents working together to accomplish complex business objectives through collaboration and decision-making. 

## Core Functionality of an Agentic AI Application
An Agentic app consists of independent agents that are specifically designed and fine-tuned to perform tasks efficiently. This application has the intelligence to invoke the appropriate agents and decide the necessary actions based on user queries, ensuring that the responses are tailored to the users' needs.

When a user submits a query to an Agentic application, the system dynamically identifies the most appropriate agent to handle the request. It then establishes the sequence of actions the chosen agent should execute to ensure effective and contextually relevant solutions. This approach enhances both efficiency and accuracy in addressing user inquiries.

To analyze the user's query, the Agentic application utilizes a large language model (LLM) to interpret the input and identify the appropriate agent based on its description. A workflow is then created to sequence the actions to be performed by the agent. For each action, the LLM extracts relevant entities from the user input and passes them to the agents to carry out the tasks. 

The responses generated by the agents are presented to the user. In cases where user queries are complex and involve multiple agents and actions, the output from one agent may be sent to another agent for further processing.

## Agentic AI vs. Traditional Automation

Compared to the existing agent platforms, Agentic AI is purpose-driven and dynamic, with sophisticated technology that delivers efficient results. These applications combine advanced reasoning, task management, and knowledge integration to ensure seamless task execution and informed decision-making. While traditional automation focuses on linear static workflows, the Agentic approach enables dynamic, intelligent orchestration that can adapt and optimize in real-time.

## Single AI Agent  vs. Agentic App

A single AI agent operates using a linear, rule-based approach, making it ideal for well-defined and repetitive tasks. It adheres to predefined workflows, which limits its adaptability. This type of agent lacks reasoning capabilities and requires explicit inputs to function effectively. Additionally, the workflow must be comprehensively defined to account for all potential cases.

In contrast, the Agentic App represents a more advanced, purpose-driven solution. It employs multiple intelligent agents that collaborate dynamically to optimize task execution and decision-making. These agents are capable of reasoning, planning, and adapting in real-time, allowing for enhanced flexibility and efficiency in various scenarios. By integrating multiple intelligent agents, the Agentic App can navigate complex situations where traditional automation would fall short, ultimately driving better outcomes and increased operational efficiency.

## Core Components of an Agentic App

Agentic applications involve the following key components that enable autonomous decision-making and complex task execution. 

![Anatomy](images/anatomy.png "Agentic App Anatomy")


**Agents**

In the context of the Agentic AI platform, agents are entities with the knowledge and resources to perform tasks or actions related to a given goal. Each agent is identified with unique core functions, objectives, and responsibilities, referred to as the **scope** of the agent. **Actions** are the building blocks of the workflows carried out by each agent for their tasks. By utilizing various tools, agents can enhance their capabilities and tackle more complex tasks. Tools allow them to access external information, data, or functionalities that they do not possess independently.

For example, In a banking setup, specialized agents can be created to handle different types of user queries, such as those related to savings accounts, card-related queries, or loan-related services, where each agent has the intelligence to take action as per the given request. Like, a dedicated agent for savings accounts can manage tasks like processing fund transfer requests, adding new payees, displaying account balances, and more. Each agent is tailored to its specific area, ensuring efficient and accurate handling of user queries and actions.

**Orchestrators**

The orchestrator manages the flow of operations and coordinates interactions between different agents and users. It ensures appropriate tasks are delegated to the right agents and that they work together effectively to achieve a broader goal. The orchestrator acts as a **supervisor** who manages and controls the agents. It is also responsible for conflict resolution and helps manage complex workflows involving multiple agents. It is responsible for interpreting the user input, delegating tasks to appropriate agents, and verifying the responses before presenting them to the user. Essentially, it is the brain of the Agentic app. 

Continuing the above banking application example, if a user requests a fund transfer from the savings account to pay off a loan, the orchestrator ensures that it first invokes the savings account agent to process the fund transfer, followed by the loan agent to update the same information and provide confirmation. In this case, the orchestrator ensures that both actions are initiated in the correct sequence and successfully completed before providing a confirmation to the user. 

**State and Conversation History**

State and history play a crucial role in decision-making and help make the interactions user-friendly and human-like. State refers to the current environment in the interaction, which can include information like user session details, recent operations performed, etc. 

Agentic applications leverage **conversation history** to enhance interactions, improve decision-making, and optimize task execution dynamically. Unlike traditional chatbots, **Agentic AI retains context**, enabling it to adapt and provide better responses.

For example, in the fund transfer scenario, the amount to be transferred might be provided by the user in the initial request. This information is stored as short-term memory until the agent reaches the actual transfer step. On the other hand, details such as the user's preferred transaction method can be classified as long-term memory.

**Tools** 

Tools are modules or special capabilities that allow the agents to access and interact with the external environments to complete their tasks. For instance, to send a confirmation email to both the payer and payee after a funds transfer, the agent must interact with the SMTP server to send email notifications.

## Example of an Agentic App

A **Banking Assistant** can be built as an **Agentic App**, where multiple specialized agents handle different banking tasks.
![Banking Example](images/banking-example.png "Banking example")

**Key Components:**

* **Orchestrator**: Acts as the central system that manages communication between users and agents.
* **Agents**: Each agent specializes in a specific banking service:
    * **Loans Manager**: Processes loan applications.
    * **Transaction Manager**: Handles payments and transactions.
    * **Cards Manager**: Manages card services like PIN reset or card blocking.
* **Tools**: Each agent has tools with built-in business logic to complete specific tasks.

This approach ensures an **organized, automated, and scalable** banking solution.
